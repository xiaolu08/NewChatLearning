# NewChatLearning 项目概述

## 摘要

`NewChatLearning` 的目标是将 JHue58/ChatLearning 的可观察功能完整迁移为 AstrBot 插件，同时保持核心学习与回复过程不调用 LLM、不主动消耗 Token。`0.1.0-beta.31.post4` 作为首个公开预览包，用于收集 Windows + AstrBot + NapCat 实机反馈；未完成项目继续保留在完整兼容验收清单中。项目保持 Beta 标识，不宣称稳定或生产可用。

## 项目定义

### 产品范围

- **问题**：Mirai 与旧 QQ 协议生态衰退后，ChatLearning 已无法自然接入当前主流 Bot 环境。
- **目标用户**：怀念或仍需要群聊自学习词库的 QQ Bot 管理员，以及希望在 AstrBot 中获得非 LLM 群聊拟人回复能力的用户。
- **项目名称**：`NewChatLearning`。
- **目标平台**：只支持 QQ 群；通过 NapCat 的 OneBot v11 接口接入 AstrBot。
- **完整性目标**：以原版的用户可观察行为和管理能力为验收基准，而非逐行照搬 Mirai HTTP 实现。
- **首版范围**：公开预览包提供核心学习、回复、迁移、管理和恢复能力；只有完整实机验收通过后才宣称达到原版完整兼容。
- **硬约束**：学习、匹配、抽样和回复不得主动调用 LLM 或产生 Token 费用。
- **现代适配**：可使用当前本地算法、数据库、AstrBot 配置页面和事件接口；任何可选 LLM 集成都必须默认关闭，且不得由插件自行触发。语音合成可以使用用户主动配置的付费云端 TTS API，但默认关闭并提供费用提醒与调用限制。
- **发布状态**：README、版本号、发布说明和仓库描述均标明公开预览 Beta / 非稳定项目，直至维护者明确批准稳定版。
- **开源边界**：原项目与 AstrBot 均采用 AGPL-3.0。直接移植将保留原项目版权归属、许可证、修改说明和源码获取方式。此处为工程合规记录，不构成法律意见。
- **学习规则**：保留原版“同一群内相邻消息构成问答；超过间隔后重开问答链”的语义，包括同一成员连续消息也可以被学习。
- **旧数据**：用户没有自己的生产词库，但提供了三份约三年前的共享 `.cl` 词库作为迁移与兼容性样本；这些数据不得默认导入运行词库。
- **媒体策略**：新学习的图片、语音等可保存媒体下载到本地长期保存，并提供可配置磁盘配额和清理机制。
- **失效内容**：旧词库中失效的媒体组件保留失效标记；回复时跳过失效组件，整条答案无可用内容时不发送。WebUI 提供扫描、预览和确认清理工具。
- **权限模型**：AstrBot 全局管理员、NewChatLearning 独立管理员、群级子管理员三层并存。
- **命令模型**：标准 `/ncl ...` 命令与原版命令别名并存，旧别名可关闭；普通成员无插件命令权限，命令触发时静默忽略，不向其发送权限提示或帮助回复。
- **学习排除**：允许学习其他 QQ 机器人和同一成员连续发言；不学习 AstrBot/NewChatLearning 管理命令和 NewChatLearning 自身回复；撤回消息若尚未固化则从学习链删除。
- **内容策略**：原样学习，只在准备回复时执行过滤。
- **部署基线**：首版仅承诺和验证 Windows。
- **LLM 协同**：本地词库命中并回复后终止当次 LLM 流程；在不调用 LLM 的前提下，尽量将该回复同步到 AstrBot 后续会话可见的历史，此能力需与记忆类插件做真实环境兼容测试。
- **WebUI**：提供类似常见 API 管理后台的高密度运维界面，包含概览、词库、学习目标、媒体、语音、规则、权限、任务、备份和诊断；WebUI 与 AstrBot 插件配置读写同一配置源，不维护两套互相漂移的设置。
- **媒体配额**：默认全局 10 GB，可配置；达到上限后停止下载新媒体但继续学习文本，且不自动删除仍有效的旧媒体。
- **隐私与保留**：默认永久保留；支持按群设置期限、删除指定成员贡献、清空指定群词库。
- **定向学习**：可将某个 QQ 用户设为学习目标；群内上一条合格消息作为问题，目标用户紧接着发送的消息作为答案，用于学习其回复风格。
- **成员贡献删除**：删除指定成员贡献的答案；其发起的问题若仍有其他答案则保留，无答案时再删除问题。执行前展示影响并自动备份。
- **静默学习**：提供区别于原版的群级静默学习模式，继续完整采集和建立词库，但禁止在该群触发任何自动词库回复。
- **WebUI 安全**：管理页面通过无密码“进入”签发一小时内存会话，不保存插件独立密码；采用会话 Cookie、CSRF、入口模式校验和高风险二次确认，并复用 AstrBot Dashboard 的页面访问边界。
- **TTS 驱动**：支持火山引擎、阿里云、腾讯云、Azure、OpenAI、OpenAI 风格 TTS，以及可映射 URL、请求头和请求体的通用 HTTP TTS。

### 调研基线

- 研究基线 ChatLearning 上游提交为 `b5b4ac3e44d35bd45aea12b542803178e783118e`，提交日期为 2024-01-30。
- 研究基线 AstrBot 为 `4.27.3`，提交 `19c029e36da451e4bef15a1adecba89dcef5e008`。
- 原版通过相邻群消息建立问答链，按答案重复次数加权随机回复，并支持正则与结巴分词余弦相似度匹配。
- 原版包含分群词库、合并词库、群标签、过滤与敏感词、黑名单、管理模式、快速删除、自定义回复、定时任务、语音回复和多种消息组件。
- 原版词库主要使用 Python pickle `.cl` 文件，配置使用 `.clc` 文本；新实现必须单独评估旧数据迁移和不可信 pickle 的安全风险。
- AstrBot 提供插件生命周期、命令/事件过滤、消息链、插件数据目录和 OneBot v11 QQ 适配能力，具备承载移植的基础条件。
- 三份共享词库均为 pickle 协议 4，静态检查未发现可调用代码的危险 opcode；受限解析后结构完整，共 107,132 个问题和 303,359 个答案。
- 样本消息类型覆盖 `Plain`、`Image`、`Face`、`Voice`、`MarketFace`、`Forward`、`Quote`、`At`、`App`、`Xml`、`File`、`FlashImage`、`MusicShare` 和 `Dice`。旧媒体引用是否仍可发送尚未验证。

### 成功标准

1. 建立逐项功能矩阵，每项原版能力都有“等价实现、平台限制、替代设计或明确延期”的结论。
2. 核心学习和回复测试能够证明没有 LLM Provider 调用路径。
3. 可在 AstrBot + NapCat 的 QQ 群环境中完成原版全部功能的端到端验收。
4. 可安全导入用户已有 `.cl` 词库，或明确提供隔离式迁移工具与风险提示。
5. 文档包含安装、配置、升级、备份、隐私、故障恢复、许可证和 Beta 警示。
6. 公开或备份到 GitHub 前由用户确认仓库、可见性和发布状态。

### 项目状态

产品需求分析已经完成并形成正式需求基线。静默学习允许管理员命令返回；WebUI 默认仅本机访问，可显式开启局域网访问，不直接支持公网暴露；云端 TTS 密钥使用 Windows DPAPI 加密，迁移机器后重新填写。后续以系统设计和验收标准为实施依据。
