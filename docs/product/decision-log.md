产品与技术方向已经确认。GitHub 私有仓库已建立为 `xiaolu08/NewChatLearning`，默认分支为 `main`，仓库保持 Beta 标识。本文保留需求讨论中影响架构、兼容性、安全和发布方式的关键决策。

### 补充设计事项

- 是否需要私聊学习或只允许私聊执行管理命令？
- `!d` / `!delete` 只允许管理员使用；普通成员所有插件命令均静默忽略。
- 过滤、敏感词和黑名单是全局共享，还是允许按群覆盖？
- 回复概率、冷却、等待时间、长度限制、@回复行为是否都要支持全局默认加单群覆盖？
- 是否需要一个只观察不回复的“影子学习”阶段，用于评估词库质量？
- 是否允许纯本地的现代算法增强，例如 MinHash、BM25、SQLite FTS 或本地嵌入模型？其中本地嵌入虽不产生 API Token，但会消耗算力和模型空间。
- 是否希望插件与 AstrBot 的 LLM 流程共存时，命中本地词库后阻止后续 LLM 回复，还是让 AstrBot 继续处理？
- 已确认命中并发送时停止当次 LLM；后续 LLM 应能看到该本地回复，具体与记忆插件的兼容性作为实机验证项。
- 数据保留期限、用户退群后的记录处理、群成员请求删除个人内容等隐私规则如何设定？
