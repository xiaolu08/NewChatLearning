# ChatLearning 功能兼容矩阵

## 摘要

已确认采用“兼容行为内核 + AstrBot 原生外壳 + 安全迁移工具”的方向。完整性按用户可观察能力验收，内部存储和并发模型允许现代化。首个可运行 Beta 必须覆盖原版全部功能；开发期间可以使用内部里程碑，但不能把缺少原版能力的版本作为完成交付。

## 兼容性分析

### 迁移原则

- 核心学习、匹配、抽样和回复路径不依赖 LLM Provider。
- 精确匹配、正则匹配、传统相似度匹配保持可分别开关和配置。
- 所有群级设置优先采用“全局默认 + 单群覆盖”的一致模型。
- 使用 AstrBot 事件与消息组件，不直接依赖 Mirai HTTP。
- 使用 SQLite 保存结构化数据；旧格式只通过显式迁移工具进入。
- 平台不支持的消息类型要可观测地跳过或降级，不静默损坏词库。

### 功能矩阵

| 领域 | 原版能力 | AstrBot 方向 | 初步风险 |
| --- | --- | --- | --- |
| 学习链 | 按群将连续消息记为问题和答案，超时后重开链 | 每群异步状态机，事件到达即事务化记录 | 重启边界、乱序、同一用户连发规则待定 |
| 词库 | 分群 `.cl` 词库 | SQLite 分群命名空间 | 旧 pickle 迁移安全 |
| 全局模式 | 定时合并所有允许群的词库 | 已实现保留来源的实时联合查询与排除群 | 大词库联合查询性能 |
| 群标签 | 多群共享标签词库 | 已实现群与标签映射；每个标签作为独立候选范围 | 多标签会按原版语义重复贡献候选权重 |
| 精确回复 | 消息链序列化后精确命中 | 规范化消息组件后哈希/结构匹配 | 图片 URL、ID 等易变字段 |
| 正则回复 | 管理员定义正则问题 | 已实现带单表达式超时的受限正则检索 | ReDoS 与非法表达式 |
| 相似回复 | jieba 词频余弦相似度 | 已实现兼容算法；默认关闭，候选索引待性能阶段 | 大词库全扫描成本 |
| 答案选择 | 按重复次数加权随机 | 保留兼容权重并可注入随机种子测试 | 历史 `same` 语义需精确复核 |
| 回复控制 | 总开关、群列表、概率、等待、冷却、长度 | AstrBot 配置与命令；支持单群覆盖 | 与 AstrBot 自身回复流程冲突 |
| @行为 | 被 @ 时强制回复并回 @ | OneBot 消息组件与事件唤醒策略协同 | 不同适配器差异 |
| 消息类型 | 文本、图片、表情、闪照、语音、转发、App、XML、JSON | 建立平台能力表与安全序列化器 | 部分类型已失效或不可重发 |
| 过滤 | 无用关键词、精确过滤、回复前复检 | 已实现包含、完全匹配、正则、组件类型及全局+群附加规则 | 正误杀与大词库规则性能待实机验证 |
| 敏感与黑名单 | 计数达到阈值后不再记录用户 | 已实现无正文命中计数、阈值封禁、全局/分群作用域和人工解封 | 用户身份跨群关联与隐私 |
| 管理模式 | 搜索、查看、删除、添加自定义问答和权重 | 已实现当前群短命令、运行模式、定向用户和主要原版群开关别名；媒体问答与 WebUI 批量管理待补 | 大结果分页与危险批量操作 |
| 快速删除 | 回复 Bot 消息 `!d` 删除对应词条 | 已实现引用真实 OneBot 消息 ID，及 `!d <序号>` 最近回复定位 | 待 NapCat 实机验收发送回执与撤回权限 |
| 自动清理 | 删除低频和命中过滤的词条 | 已实现按群过滤命中预览、备份和事务删除；定时/低频策略待补 | 大词库扫描性能与误删风险 |
| 成员贡献删除 | 按成员移除已学习内容 | 已实现按群两阶段预览、共享答案减权、独占答案删除、待固化消息清理与执行前备份 | NapCat 身份稳定性与高并发陈旧计划 |
| 定时任务 | 文件语法定时执行命令与发消息 | AstrBot 生命周期内调度器 | 任意路径图片与命令执行风险 |
| 语音回复 | 外接本地语音合成项目 | 已实现 Windows、GPT-SoVITS、通用本地 HTTP；云端厂商与 DPAPI 待补 | 模型体积、维护状态、平台格式 |
| 导入导出 | 词库导入、Excel 导出 | 已实现旧 `.cl` 隔离扫描、JSONL 转换、备份与事务导入；当前群可导出带安全 XLSX 预览和完整问答 JSONL 的 ZIP | 旧媒体有效性、旧 `.cl` 反向导出与大库耗时 |
| 运维 | 控制台配置、检查、更新 | AstrBot 配置页、日志、统计、备份 | 配置热更新和数据一致性 |
| 审计 | 管理操作过程记录 | 已实现登录保护、动作筛选、游标分页和服务端脱敏摘要的 WebUI 页面 | 未实现模块的高风险动作仍需补齐记录 |

### 已确认的 AstrBot 原生增强

- 插件内置管理 WebUI，至少提供媒体健康扫描、失效标记统计、影响预览和二次确认清理。
- WebUI 采用运维后台式信息架构，概览统计包含问题数、答案数、消息组件数、媒体占用、当前学习群和按用户筛选的学习目标。
- WebUI 与 AstrBot 插件配置共用一个配置服务和版本号；聊天命令、WebUI、AstrBot 配置页均写入同一数据源。
- 新媒体尽量下载到插件数据目录，记录内容哈希、来源类型、大小、状态和最后验证时间。
- 本地回复通过 AstrBot 正常消息结果发送并停止当次事件，避免继续触发 LLM。
- 在不发起模型请求的前提下，将本地回复以 Bot 消息同步进 AstrBot 可用的消息/会话历史；若核心接口或记忆插件不兼容，允许通过配置关闭并在诊断页显示状态。
- 首版测试矩阵限定 Windows + AstrBot + NapCat，其他系统不作兼容承诺。
- TTS 采用可插拔驱动：Windows 本地 TTS、通用本地 HTTP、GPT-SoVITS、付费云端 API。付费驱动默认关闭，显示计费警示并支持频率/日额度限制。
- 普通成员不具备任何插件命令权限；命令匹配后静默忽略，避免触发命令回复。快速删除仅限管理员并记录审计日志。
- 媒体默认配额 10 GB，超限后仅停止新增媒体保存；失效清理默认按组件处理，清空答案前再次确认。
- 新增群级静默学习模式：学习流水线正常运行，自动回复流水线无条件短路；状态、统计和审计中明确显示静默目标。
- 新增定向用户学习：问题来自目标用户发言前的合格群消息，答案只采集目标用户的紧随回复；数据库保留贡献者 ID 以支持按成员删除。
- WebUI 认证不照搬参考项目的 MD5 方案。密码使用 Argon2id（依赖不可用时使用标准库 scrypt），会话 Cookie 设置 HttpOnly、SameSite 和合理有效期，所有修改操作要求 CSRF 校验。
- 登录失败按 IP 和账户双维度限流并临时锁定；登录会话有效期为一小时，会话内不重复输入密码，高风险操作要求二次确认并进入审计日志。
- 默认仅绑定 `127.0.0.1`，允许管理员显式开启局域网监听；不提供直接公网暴露模式，也不信任未经配置的转发头。
- TTS 密钥使用 Windows DPAPI 加密，不进入普通配置导出或日志，WebUI 仅显示掩码；换机恢复后要求重新填写。
- 静默学习群仍允许管理员命令返回结果，自动词库回复无条件禁用。
- 标准群设置命令与原版兼容别名共用 AstrBot 配置持久化、revision 冲突保护和审计；别名只作用于当前群，禁止普通成员触发回复或把命令写入学习链。

### 现代适配候选

- **推荐默认**：SQLite + FTS/倒排候选 + jieba 兼容相似度，不下载模型、不调用网络服务。
- **可选本地增强**：用户主动安装的本地嵌入模型或 reranker；必须明确标记“零 API Token，但会消耗本机资源”，且默认关闭。
- **不纳入核心**：任何自动调用云端 LLM 来总结、清洗、审核、生成答案或补全词库的功能。
- **可扩展接口**：允许其他插件显式查询本地词库，但 ChatLearning 自身不注册会被 Agent 自动调用的 LLM 工具，除非未来另行确认。

### 内部开发里程碑

以下仅用于组织开发，任何中间里程碑都不视为用户要求的“首个可运行 Beta”：

1. **内核里程碑**：文本学习、精确/正则/余弦回复、权重、概率、冷却、过滤和 SQLite。
2. **QQ 适配里程碑**：NapCat 消息组件、群标签、合并词库、快速删除和群级权限。
3. **管理迁移里程碑**：旧 `.cl` 隔离导入、搜索删除、自定义问答、备份和导出。
4. **长尾功能里程碑**：定时任务、语音、转发与卡片类消息、压力和恢复测试。
5. **首个可运行 Beta**：上述矩阵全部达到“实现、验证或明确的平台等价降级”标准后统一发布。
6. **后续 Beta**：新设计、AstrBot/NapCat 兼容和 Bug 修复。
7. **正式版候选**：真实群灰度、文档和许可证审计完成，并由用户明确批准解除 Beta 标识。

### 旧词库样本审计

| 样本 | 问题数 | 答案数 | 主要特点 |
| --- | ---: | ---: | --- |
| 高频共享词库 | 2,266 | 23,891 | 以文本、表情为主，含语音、卡片、文件等类型 |
| 未过滤综合词库 | 82,965 | 107,858 | 含约 4.2 万条图片组件及大量未过滤内容 |
| 抽象共享词库 | 21,901 | 171,610 | 单问题最多 5,157 个答案，含约 3.9 万条图片组件 |

三份样本结构完整，均为协议 4 的纯基础容器 pickle，静态检查未发现代码调用 opcode。迁移器仍必须采用受限解析，并把内容安全、媒体引用有效性和结构兼容分开报告。

实际导入验证已使用 2.1 MB 高频共享词库在临时数据库完成：原始 2,266 个问题、23,891 个答案中，2,206 个问题和 23,841 条答案记录可转换；60 个问题因无可转换答案跳过，另有 8 条答案组件无法解析。规范化合并后形成 22,877 个唯一答案，最大保留权重为 440；运行数据库与导入前备份的 `PRAGMA quick_check` 均为 `ok`。该验证未写入插件运行数据。

### 开源与发布策略

- 仓库许可证建议保持 `AGPL-3.0-only`，最终 SPDX 表达式在发布前复核。
- 保留原 ChatLearning 作者与仓库链接，在 NOTICE 或 README 中说明这是面向 AstrBot 的修改/移植版本。
- 新增代码标注新贡献者版权，不删除原有版权声明。
- README 顶部、插件 metadata 描述、版本号和 GitHub 仓库描述均显示 Beta。
- 不用“禁止生产使用”“禁止商用”等附加限制破坏 AGPL 权利；风险通过醒目的非正式/无担保说明表达。
- 公开网络部署时提供对应源码访问入口，满足 AGPL 网络交互条款的工程要求。
