# NewChatLearning 系统设计

## 摘要

实现采用分层异步架构：AstrBot/NapCat 适配层只负责事件与消息转换，领域层负责学习和回复规则，SQLite 仓储负责一致性，WebUI 与聊天命令通过同一应用服务操作数据。公开预览 Beta 可在明确列出限制的前提下用于社区验证；完成全功能实机验收后才可宣称达到完整兼容 Beta。

### 核心流水线

1. **事件接收**：只接收 NapCat/OneBot QQ 群消息、撤回通知和必要的群成员事件。
2. **命令判定**：优先识别 `/ncl` 与旧命令；普通成员命令静默终止，管理员命令进入命令服务且不得参与学习。
3. **消息规范化**：将 AstrBot 组件转换为稳定的内部组件 JSON，剥离 URL、消息 ID 等易变字段用于问题匹配，同时保留可发送字段和来源元数据。
4. **学习判定**：排除自身消息和命令；在媒体下载前检查全局/分群黑名单和敏感词阈值，再依据群模式、间隔、定向用户规则和撤回状态更新学习链。
5. **持久化**：问题、答案、贡献者、组件和媒体在单次事务中写入；重复答案增加权重和最后出现时间。
6. **回复检索**：按精确、正则、传统相似度顺序检索，先按类型阈值筛选，再剔除命中包含、完全匹配、正则、敏感词或组件类型规则的候选，最后应用权重、概率、冷却和长度限制。
7. **发送与协同**：媒体可用性降级后发送；成功时记录回复映射、停止当次 LLM，并尝试写入 AstrBot 会话历史。

### 词库作用域

- 普通模式只查询当前群的问答，默认不跨群泄漏学习内容。
- 全局模式实时联合未被排除、且未进入标签体系的群，不生成 `Merge.cl` 或复制问题答案。
- 配置标签的群只查询与自己共享标签的群；多个标签分别形成候选范围，同一答案可像原版多个标签词库一样重复贡献抽样权重。
- 问题频次、答案权重、贡献者和媒体引用仍保留原群来源，便于后续按群管理、备份和删除。

### 运行模式

| 模式 | 学习 | 自动词库回复 | 管理员命令 |
| --- | --- | --- | --- |
| 关闭 | 否 | 否 | 是 |
| 仅学习 | 是 | 否 | 是 |
| 学习并回复 | 是 | 是 | 是 |
| 仅回复 | 否 | 是 | 是 |
| 静默学习 | 是 | 永不 | 是 |
| 定向学习 | 仅目标用户答案 | 按群回复设置 | 是 |

### 命令设计

- 主入口：`/ncl help`、`/ncl status`、`/ncl learning`、`/ncl reply`、`/ncl silent`、`/ncl target`、`/ncl library`、`/ncl media`、`/ncl tts`、`/ncl task`、`/ncl admin`。
- Beta 25 已实现当前群 `/ncl mode [disabled|learning|reply|learning_reply|silent]`、`/ncl learning on|off`、`/ncl reply on|off`、`/ncl silent on|off` 和 `/ncl target list|add|remove|clear`。开关命令只改变对应能力并保留另一项；定向用户只有在学习模式下才能新增。
- 当前已兼容的原版入口包括 `!learning`、`!reply`、`!grouplist` 和 `!add/!remove learning|learnings|reply|tag|subadmin|unmerge`。`!learning` 与 `!reply` 在管理员私聊中切换全局主开关，在群聊中切换当前群能力；带群号的跨群命令可从任意管理群或管理员私聊发出，不需要进入目标群。跨群命令只允许 AstrBot 全局管理员或插件管理员执行；群聊子管理员和普通成员被静默截断，命令消息不进入学习链。
- 跨群写入在一次配置 revision 校验和一次持久化中原子更新学习群、回复群、静默群、共享标签、全局词库排除群及子管理员。`remove tag` 清除目标群全部标签。`add subadmin` 通过 AstrBot 的 NapCat 群资料接口读取目标群当前群主和群管理员，读取任一目标失败则整批不保存；再次执行可刷新授权名单。
- 当前词库管理命令：`/ncl search <关键词>`、`/ncl show <问题ID>`、`/ncl add <问题> => <答案>`、`/ncl add-regex <表达式> => <答案>`、`/ncl weight <答案ID> <权重>`、`/ncl delete-answer <答案ID>`、`/ncl delete-question <问题ID>`。
- 词库管理命令始终限定当前群作用域。全局管理员和插件管理员仍按当前群操作；群子管理员不能借助问题或答案 ID 访问其他群。
- WebUI 词库页复用同一应用服务；读取要求一小时服务端会话，新增与权重修改要求 CSRF，答案和问题删除还要求二次确认与删除前数据库备份。
- WebUI 群聊页直接更新 AstrBot 注入的插件配置对象，并调用其持久化接口。保存携带配置 revision；页面版本过期时返回冲突，不覆盖 AstrBot 配置页或其他入口刚写入的设置。
- WebUI 过滤页与 AstrBot 配置共用 `filters` 数据源。全局规则与群聊附加规则相加；规则试跑不写命中记录，保存使用 revision 冲突保护，人工封禁与解封写审计日志。
- 过滤词库清理按群扫描历史答案，只返回命中数量、规则类型分布和可能变空的问题数。管理员主动操作继续使用绑定 WebUI 操作者、群、配置 revision 和一小时有效期的两阶段计划；确认后先备份，随后在单事务中重新校验并删除命中答案。
- 定时任务只允许媒体健康扫描、数据库备份、过期产物清理和过滤词库清理四种内建动作，不接受命令、脚本或任意路径。过滤清理默认为只读预演；自动删除在保存和手动执行时均要求明确确认，每次运行重新计算候选、先备份再事务删除。
- 调度器在插件启动后恢复中断状态并在插件停止前取消后台循环。计划执行前先原子认领并推进下次执行时间，避免 AstrBot 重载后立即重复执行；失败只记录固定原因和数量摘要，不终止后续调度。
- 备份恢复只接受插件备份目录内的 SQLite 文件。页面先执行只读完整性和 schema 检查；恢复要求二次确认，先保存当前数据库，再关闭 WAL 连接并原子替换。恢复成功后全部 WebUI 会话失效，失败时自动回滚当前数据库保险备份。
- WebUI 权限页与 AstrBot 配置页共用 `permissions` 数据源。保存要求一小时内有效的登录会话、CSRF、二次确认和配置 revision；AstrBot 全局管理员始终优先，审计只记录管理员数量和受影响群数。
- 定向学习保留相邻消息链：所有合格消息都可成为下一条问题，只有目标用户的紧随消息会被固化为答案。未配置目标用户时保持原版全成员学习语义。
- 原版别名保持可用并可整体关闭；所有别名映射到同一应用服务。
- 快速删除 `!d` / `!delete` 仅管理员可用，必须引用 NewChatLearning 最近发送的可追溯回复。
- 高风险批量操作优先引导至 WebUI，不在群聊中展示敏感内容。
- Beta 26 的当前群词库导出只在登录后的 WebUI 提供，不通过 QQ 群发送。确认请求使用 POST、CSRF 和布尔确认标记生成文件及五分钟一次性下载票据；GET 下载仍要求同一小时会话有效，票据绑定会话且成功使用后立即失效。
- 导出先以 SQLite 在线备份取得一致性快照，再在线程中流式生成 ZIP。包内 XLSX 用于人工查看，文本单元格防公式注入并受 Excel 长度限制；JSONL 保留群号、问题/答案 ID、规范化键、完整组件、频次、权重和时间戳。临时快照在生成后删除，导出包 24 小时后由后续导出清理。

### TTS

- 驱动：Windows 本地、GPT-SoVITS、通用本地 HTTP、火山、阿里、腾讯、Azure、OpenAI、OpenAI 风格、自定义 HTTP 映射。
- 驱动统一实现健康检查、文本限制、音色列表、合成、超时、重试、费用类别和错误脱敏。
- 云端 TTS 默认关闭，支持每分钟、每日调用数和每日字符数限制。

Beta 24 已实现第一阶段本地驱动：Windows 使用 `System.Speech` 生成临时 WAV；GPT-SoVITS 按本地 `/tts` JSON 接口调用；通用本地 HTTP 发送 `text`、`voice` 与 `format`。HTTP 驱动只接受带显式端口的字面量环回地址，禁用系统代理和重定向，单次响应限制 10 MB。生成音频保存到插件临时目录并清理超过 24 小时的文件。

语音只替换完全由纯文本组成的词库答案，`At` 组件可忽略；图片、文件或其他混合答案保持原消息链。概率未命中、文本过长、驱动不可用、超时或音频格式无效时均回退原文本，不阻断本地词库回复。发送给 QQ 的消息可为语音，但写入 AstrBot 历史的是原文本链，便于后续 LLM 或记忆插件理解 Bot 已说过的内容。

付费云端驱动、DPAPI 密钥、额度与厂商健康检查仍未实现，因此当前配置保存主动拒绝云端驱动；旧配置中已有的云端驱动只显示为不可用并回退文本。

### 旧数据迁移

- 上传后先做 pickle opcode 静态扫描，拒绝包含对象构造、全局调用、持久 ID 的文件。
- `/ncl migrate-scan` 只允许管理员调用；扫描在独立 Python 进程执行，主进程只接收 JSON 报告，不加载外部 pickle 对象。
- 使用只允许基础容器的受限 Unpickler，并以独立进程设置内存和时间限制。
- 迁移前展示问题/答案/类型/失效媒体统计；用户确认后写入暂存区，再原子合并。
- `migrate-prepare` 在隔离进程把 pickle 转成中立 JSONL 和 SHA-256 清单；`migrate-apply <ID> confirm` 才会为当前群创建数据库备份并以单事务流式导入。
- Beta 27 的 WebUI 迁移页不接受服务器路径。AstrBot 原生上传 bridge 将单个 `.cl` 文件送入插件临时目录，服务端执行扩展名、128 MB 上限、票据、会话、实际字节数和随机文件名约束；扫描通过后才允许创建绑定会话与目标群的一小时导入计划。浏览器只接收结构计数和文件名，不接收路径或词库正文。
- 原版答案的实际权重按 `same + 1` 迁移；问题 `freq` 和 `regular` 分别映射为频次与正则标记。导入成功不会修改学习或回复开关。
- 反向导出从 SQLite 一致性快照构造仅含基础容器的协议 4 `.cl`；问题频次写入 `freq`，正则标记写入 `regular`，答案权重按 `same = weight - 1` 写回。不可便携的本地媒体降级为文本，不导出插件路径。
- 任何导入不自动启用回复，也不绕过过滤规则。

### 可观测性

- 指标：问题数、答案数、今日学习量、命中率、过滤量、回复量、媒体占用、失效量、TTS 调用和错误。
- 日志禁止记录密钥、完整敏感消息和 TTS 请求头；诊断包默认脱敏。
- 所有配置修改、导入、删除、恢复、权限变化和登录事件进入审计日志。
