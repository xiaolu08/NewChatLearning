# NewChatLearning 数据模型

## 摘要

SQLite 数据库需要同时支持原版问答权重语义、群/标签/全局检索、贡献追踪、媒体生命周期、权限和审计。问题与答案必须分表，消息组件使用版本化 JSON；所有删除默认软删除或先备份，以支持预览和恢复。

## 数据设计

### 主要实体

| 实体 | 关键字段 | 用途 |
| --- | --- | --- |
| `groups` | `group_id`、模式、学习/回复覆盖配置、保留期 | 群级控制 |
| `learning_targets` | 群、目标 QQ、启用时间 | 定向用户学习 |
| `questions` | 群/词库域、规范化哈希、组件 JSON、纯文本、频次、正则标志 | 问题索引与三级匹配 |
| `answers` | 问题 ID、组件 JSON、权重、首次/最后出现、状态 | 候选答案 |
| `contributions` | 消息 ID、发送者、问题/答案关联、时间 | 撤回和按成员删除 |
| `pending_messages` | 平台、群、发送者、消息 ID、时间、组件 JSON | 跨重启保存尚未固化的学习链尾部 |
| `media_assets` | 哈希、类型、路径、大小、状态、来源、最后检查 | 媒体去重和清理 |
| `answer_media` | 答案与媒体关系、组件位置 | 失效组件降级 |
| `tags` / `group_tags` | 标签和群关系 | 标签词库 |
| AstrBot `library.share_groups` 配置 | 联动组名称、成员群号、可选新成员欢迎语 | 只联合直接成员群的本群词库；欢迎语仅响应成员群的入群通知，不递归传播其他权限 |
| AstrBot `filters` 配置 | 规则、类型、作用域、启用状态、群附加规则 | 回复前过滤与敏感词判定 |
| `blacklist_state` | 全局/群作用域、用户、命中计数、封禁与人工标记 | 阻止后续学习 |
| `filter_hits` | 群、用户摘要字段、规则类型、方向、时间 | 不含消息正文的命中统计 |
| `admins` | QQ、角色、群范围 | 三层权限 |
| `reply_records` | QQ 消息 ID、答案 ID、发送时间 | 快速删除和追踪 |
| `repeat_reply_events` | 群号、成功触发时间 | 每群滚动一小时复读回复限流 |
| `external_libraries` | 词库 ID、名称、来源摘要、启用状态、版本和计数 | 可独立管理的导入词库 |
| `external_library_bindings` | 词库 ID、目标群 | 外部词库按群生效范围 |
| `scheduled_tasks` | 计划、动作、目标、状态 | 定时任务 |
| `settings` | 键、JSON 值、版本、来源、时间 | 单一配置源 |
| `audit_logs` | 操作者、动作、对象、摘要、时间、结果 | 审计 |
| `backups` | 路径、范围、校验和、创建原因 | 恢复 |

### 组件 JSON

每个组件包含 `schema_version`、`type`、稳定匹配字段、可发送字段和平台扩展。问题匹配表示必须排除临时 URL、文件路径、OneBot 消息 ID；答案发送表示可引用本地媒体哈希。未知类型原样保存在 `raw` 中并标为不可发送，不得因新版组件导致整个词条损坏。

### 一致性规则

- 相同规范化问题在同一词库域内唯一。
- 相同答案组件序列增加权重，不重复创建答案。
- 媒体按内容哈希去重；删除答案只在无引用时回收媒体。
- 撤回尚未固化消息时回滚学习链；已固化贡献保留审计并按配置处理。
- 删除成员贡献前建立范围备份；只删除其答案贡献，问题无答案后再删除。
- 配置更新使用递增版本进行乐观并发控制。

### 索引

- 问题：`library_scope + normalized_hash` 唯一索引。
- 答案：`question_id + normalized_hash` 唯一索引。
- 贡献：`platform_message_id`、`sender_id + group_id + created_at`。
- 媒体：`content_hash` 唯一索引，`status + last_checked_at` 维护索引。
- 文本候选：SQLite FTS 表保存可检索纯文本；最终相似度仍使用兼容算法确认。

当前 schema v3 已在 `questions` 中加入 `plain_text` 与 `is_regex`。从 schema v1/v2 升级时，会从问题组件 JSON 的首个文本组件回填纯文本；自动学习的问题保持非正则，只有受权限控制的自定义问答和旧词库迁移可以设置正则标记。FTS 候选索引留待大词库性能阶段加入。

schema v4 为 `media_assets` 增加原始名称和远程来源字段，并把旧 `available` 状态迁移为 `healthy`。消息组件只保存 `media_path` 相对路径和内容哈希，不保存成功本地化后的 Base64 或本机绝对路径。

schema v5 实现 `reply_records`。本地词库回复通过 NapCat 成功发送并取得真实 OneBot 消息 ID 后，保存消息、答案、问题和群的关联。管理员快速删除会精确删除关联答案；问题不再含答案时同步删除问题，并将操作写入 `audit_log`。同一答案的其他历史回复记录会一起失效，避免重复删除。

schema v6 增加 `legacy_imports`，登记导入 ID、目标群、来源文件名、暂存 SHA-256、实际问题/答案数和操作者。导入 ID 只能成功应用一次；JSONL 合并与审计写入位于同一事务，异常时整体回滚。

schema v7 实现 `answer_media`，按答案和组件位置保存媒体类型、哈希、相对路径、远程来源、健康状态、原因与检查时间。扫描只回填引用和状态，不修改答案组件 JSON，也不删除答案。状态包括 `healthy`、`missing`、`expired_remote`、`unsupported` 和 `quarantined`；本地路径必须位于插件数据目录内，已有哈希会重新校验。远程旧链接的基础扫描只验证 URL 结构、DNS 解析和公网地址边界，不下载文件，因此 `healthy` 仅表示该引用通过基础安全检查，不承诺远端内容仍可访问。

schema v8 实现 `blacklist_state` 与 `filter_hits`。敏感关键词命中只累计用户、作用域和次数，不保存消息正文；达到阈值的当前消息及后续消息不进入学习链。人工解封会清零命中次数。普通包含、完全匹配、正则和组件类型规则只在回复候选抽样前生效，不修改原始词库。

schema v9 实现 `scheduled_tasks` 与 `scheduled_task_runs`。任务定义只保存固定动作类型、可选群号、启用状态、分钟间隔、过滤清理策略、乐观并发 revision 和运行时间；执行历史只保存触发方式、固定状态及不含聊天正文、用户、凭据和路径的数量摘要。自动执行在事务内把任务标为 `running` 并提前推进下次时间；插件重启会把残留运行记录改为 `interrupted`，不会立即重复认领。

schema v11 增加 `external_libraries` 与 `external_library_bindings`。新导入内容使用 `external:<library_id>` 词库域，不再与群聊自产问答合并；回复查询只加入当前目标群绑定且已启用的外部域。更新在同一事务内清空该外部域并写入新版本，删除只移除对应外部域及元数据。停用和绑定修改不改问答内容。执行更新或删除前创建完整 SQLite 备份，审计只记录词库 ID、版本、绑定数量和问答计数。schema v10 仅包含 TTS 用量表，因此这里保留版本连续性。

schema v12 增加 `repeat_reply_events`。只有答案与实际触发消息的规范化键一致且消息成功发送后才写入事件；决策时只统计当前群最近 3600 秒内的记录。表中不保存消息正文、用户、答案或问题内容，超过一天的旧事件在后续写入时清理。

过滤规则词库清理不增加数据库表。准备阶段把计划保存在插件临时目录，只记录群、操作者摘要、配置 revision、答案 ID、问题 ID、答案内容 SHA-256 和命中规则类型，不保存答案正文或规则文本。执行前创建通过完整性检查的 SQLite 备份；事务内再次验证答案归属和内容哈希，任一记录变化则整批回滚。删除答案会同步失效回复追踪，并清理无剩余答案的问题。

数据库恢复同样不增加 schema。候选文件只能来自插件 `backups` 目录且扩展名为 `.sqlite3`；只读检查确认 `quick_check`、schema 元数据和版本范围后才允许恢复。执行时先用 SQLite 在线备份保存当前数据库，再把候选复制到同目录临时文件复检，完成 WAL checkpoint、关闭连接和 sidecar 清理后原子替换。重新建连会执行与正常启动相同的 schema 迁移；若替换或建连失败，则用保险备份自动回滚。

成员贡献清理不增加 schema，使用现有 `contributions` 表作为唯一归属证据。预览按群和成员汇总每个答案的贡献次数与当前权重；执行前重新比较完整操作清单。贡献次数小于答案权重时仅扣减权重并删除对应贡献行，贡献次数达到当前权重时删除答案并失效其回复追踪；问题无剩余答案才删除。该成员在本群的待固化消息同步清理。导入答案和管理员自定义答案没有贡献记录，不会被成员清理推测删除。

审计查询不增加 schema，使用 `audit_log.id` 作为倒序游标并可按动作精确筛选。数据库层只负责分页读取，应用层将 `details_json` 转换为白名单摘要；任何未明确允许的字段不会进入 WebUI。该接口不支持全文搜索，以免把聊天正文或未来新增敏感字段变成可检索面。

当前群词库导出不增加 schema。生成前使用 SQLite 在线备份取得单一时间点的一致性快照，随后关闭对运行数据库的长期读取并在线程中流式生成文件。JSONL 每行保存群号、问题/答案 ID、规范化键、完整组件、正则标记、频次、权重和创建/更新时间；XLSX 只提供人工查看列，超长文本按 Excel 单元格限制截断并清除 XML 非法字符，公式前缀使用文本转义。导出不包含待固化消息、贡献、媒体二进制、黑名单、审计或配置，因此不等同数据库备份，也不能直接作为完整恢复文件。

清理影响预览按失效组件计算受影响答案、问题和群，并区分移除失效组件后仍可发送与将变为空答案两种情况。后续清理执行仍必须建立备份、显示预览并得到明确确认。

媒体清理使用一小时有效的两阶段计划。计划绑定群和创建管理员；确认执行前建立 SQLite 在线备份，并在单个事务内重新校验答案内容摘要与失效组件状态。默认 `prune` 模式只移除失效组件，答案不再含可发送组件时才删除；显式 `drop-answer` 模式删除所有包含失效媒体的答案。裁剪后会重算匹配键；若与同问题下已有答案相同，则合并权重、贡献记录和回复追踪。执行结果写入审计日志，完成后重新扫描媒体引用。
